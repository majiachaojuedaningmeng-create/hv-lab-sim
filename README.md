# 高压系统与特种设备集成 · 虚拟仿真实验

> 一个可以反复做错的高压上电实验。做错的代价是零，做错的后果一点都不打折。

单文件网页实验：把动力电池高压系统从「设计参数 → 预充上电 → 绝缘监测 → 故障处置 → LOTO 恢复」
完整走一遍，每一步都会真的算，选错参数会把流程带进失败分支。

双击 `index.html` 就能跑。不需要联网、不需要安装、不上传任何数据。

在线版：**https://majiachaojuedaningmeng-create.github.io/hv-lab-sim/**

## 为什么做这个

高压系统的教学有个绕不开的矛盾：

- 真设备上不能让学生犯错 —— 高压误操作、未验电、联锁旁路，任何一个都是人身事故。
- 但不错过一遍就记不住 —— 安全规程背得再熟，也不等于遇到「预充失败」时知道先查哪里。

虚拟仿真把这两件事同时解决了：**出错不伤人，但出错会被记下来**。实验里有一条「红线记录」，
未隔离验电、擅自提高保护阈值、联锁未通过强行启动这类操作，一旦发生就进违规档案，
最后在复盘页里逐条摊开 —— 这比嘴上说一百遍「注意安全」管用。

## 实验内容

| 模块 | 做什么 |
|---|---|
| 教学目标 | 实验要建立的能力与判定标准 |
| 设计参数 | 母线电压、电容、预充电阻等参数选择，改动会传导到后续判定 |
| 模型校核 | 预充动力学、能量与电阻应力、短路电流的核算 |
| 安全操作与故障处置 | 完整操作流程，含四个故障场景的分支 |
| 设备属性与合规核验 | 器件容量、耐压等级与工况是否匹配 |
| LOTO 记录与操作时序 | 上锁挂牌的执行顺序与记录留痕 |
| 实验成果 | 参数表、判定结论与评分 |
| 违规记录与复盘 | 含「红线」违规的逐条回溯 |
| 进度存档 | 进度存在浏览器本地，关掉再开能接着做 |

流程步骤编号到第 23 步，其中第 17 步是预充上电、第 18 步是预充失败分支 ——
如果预充电阻选得不对，会在这里被卡住，而不是在最后评分时才发现。

### 物理模型

不是选项题，是真的算：

```text
预充过程   一阶 RC（母线电容 2 mF），输出时间常数 τ 与 90% 母线电压建立时间
预充能量   ½ C U²，同时算预充电阻需要吸收的能量与峰值功率
失败判据   预充过慢 → 主接触器闭合时母线电压不足 → 二次涌流与拉弧
断路风险   预充过程中断开 → 母线电容无放电路径 → 保持在断开瞬间的电压
```

参数、模型、流程判定三者是联动的：改一个电阻值，后面几步的结论会跟着变。

## 工程实现

- **单文件**。HTML + CSS + JS + three.js 全部内联在一个 752 KB 的文件里，没有任何 `src`/`href` 外部引用。
  这样做的原因很实际：教室机房的网络不可靠，U 盘拷过去双击就得能开。
- **零外部请求**。所有资源本地化，断网可用，也不会因为 CDN 挂了而黑屏。
- **三维部分**用 three.js（内联），呈现高压柜等设备的空间关系与柜门联锁状态；WebGL 不可用时流程与计算仍可正常完成。
- **存档**用 `localStorage`，不经过任何服务器。

## 已知边界

写在前面，避免误用：

1. **是教学模型，不是工程仿真。** 一阶 RC、简化短路电流估算足够讲清原理，
   但不能替代真实系统的设计校核（真实工况要考虑接触器弹跳、线束电感、温度对阻值的影响）。
2. **结论的正确性依赖参数库。** 参数取值的依据写在模型校核里，脱离工况单独看数值没有意义。
3. **依赖 WebGL 的硬件加速。** 部分老机器或远程桌面下三维区域会空白，流程仍可完成。
4. **成绩只存在本机。** 换浏览器或开隐私模式会读不到，这是故意的 —— 数据不出本机。
